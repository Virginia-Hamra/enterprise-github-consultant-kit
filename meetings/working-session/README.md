# Working Session Playbooks

Hands-on co-build / co-design session playbooks. Each playbook: **objective → DoD → pre-reqs → step-by-step → validation → rollback**.

| Playbook | Outcome | Duration |
|---|---|---|
| `identity-onboarding-session.md` | SSO + SCIM configured & validated | 2–3h |
| `repo-governance-session.md` | Rulesets deployed org-wide via IaC | 2–3h |
| `ghas-enablement-session.md` | GHAS turned on for pilot cohort | 2h |
| `actions-migration-session.md` | One pipeline migrated to Actions | 3h |
| `oidc-cloud-auth-session.md` | OIDC trust to cloud configured | 2h |
| `audit-streaming-session.md` | Audit log streaming → SIEM live | 2h |
| `copilot-rollout-session.md` | Pilot cohort enabled with policy | 1.5h |
| `migration-wave-session.md` | One migration wave executed | 3–4h |

> Working sessions are **destructive by design** — they make real changes. Always: pre-req checklist, change approval, rollback plan, and customer driver in the seat.
